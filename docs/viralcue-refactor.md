# **Technical Specification: Twitch Viral Moment SaaS**

**Version:** 1.0 **Target Infrastructure:** Google Cloud Platform (GCP) **Architecture Style:** Event-Driven Microservices **Core Objective:** Real-time monitoring of Twitch streams to identify viral moments, generate clips, and automate affiliate marketing using Multimodal AI.

---

## **1\. High-Level Architecture**

The system utilizes a **Hub-and-Spoke** model centered around **Google Cloud Pub/Sub**. Services are decoupled and communicate strictly via asynchronous events.

### **Core Components**

1. **Ingress/Monitoring:** GKE Autopilot (Stateful WebSocket connections).  
2. **Event Bus:** Cloud Pub/Sub.  
3. **Compute (Job-Based):** Cloud Run Jobs (Video fetching/processing).  
4. **AI Engine:** Vertex AI (Gemini 1.5 Pro).  
5. **Storage:**  
   * **Relational:** Cloud SQL (PostgreSQL) for User/Auth/Affiliate Data.  
   * **Document/Real-time:** Firestore for UI Cards, Drafts, and Events.  
   * **Blob:** Google Cloud Storage (GCS) for video clips.

## **3\. Microservices Breakdown**

### **Service A: The Sentinel Swarm**

* **Infrastructure:** **GKE Autopilot** (Kubernetes).  
* **Language:** Node.js (High concurrency) or Go.  
* **Responsibility:** Maintains persistent connections to Twitch Chat and Audio streams.  
* **Logic:**  
  * Connects to 50 channels per pod.  
  * **Input:** Twitch Chat IRC (WebSocket) \+ HLS Audio Stream.  
  * **Trigger 1 (Viral):** Calculates `HypeScore` (Chat Velocity \+ Audio Energy). If `Score > Threshold`, publishes `event.viral_candidate`.  
  * **Trigger 2 (Affiliate):** Buffers last 10s of audio. Runs local STT (Whisper-tiny) every 5s. If keyword found, publishes `event.affiliate_trigger`.

### **Service B: The Time Traveler (Sniper)**

* **Infrastructure:** **Cloud Run Job**.  
* **Language:** Python.  
* **Responsibility:** Fetches historical video without 24/7 recording.  
* **Trigger:** `event.viral_candidate` (Pub/Sub).  
* **Process:**  
  1. Fetches `user_secrets` from SQL.  
  2. Authenticates with Twitch API as the Streamer.  
  3. Requests **Active VOD** Manifest.  
  4. Calculates segment range (`EventTime - 60s` to `EventTime + 10s`).  
  5. Downloads `.ts` segments.  
  6. Stitches to `.mp4` (ffmpeg copy).  
  7. Uploads to GCS Bucket `gs://raw-clips`.  
  8. Publishes `event.clip_downloaded`.

### **Service C: The Director (AI Engine)**

* **Infrastructure:** **Cloud Run Service** \+ **Vertex AI**.  
* **Language:** Python.  
* **Trigger:** `event.clip_downloaded` (Pub/Sub).  
* **Process:**  
  1. Generates signed URL for the GCS video.  
  2. **Call Vertex AI (Gemini 1.5 Pro):**  
     * Passes Video File \+ User Persona (from SQL).  
     * Requests: Score, Summary, Draft Tweets, Draft TikTok Captions.  
  3. **Result:**  
     * If `Score < 40`: Deletes video, logs event, stops.  
     * If `Score >= 40`: Writes document to **Firestore** (`users/{id}/cards`).

### **Service D: The Publisher**

* **Infrastructure:** **Cloud Functions (2nd Gen)**.  
* **Trigger 1:** `event.card_approved` (Firestore `onUpdate` trigger).  
  * **Action:** Uploads video/text to Twitter/TikTok APIs. Updates Firestore status to `published`.  
* **Trigger 2:** `event.affiliate_trigger` (Pub/Sub).  
  * **Action:** Checks SQL `last_posted_at` for cooldown. If valid, posts link to Twitch Chat via API. Updates SQL.

## **5\. Event Sequences & Data Flow**

### **Scenario 1: The Viral Moment**

1. **\[GKE Sentinel\]** detects Audio \> 90dB & Chat \> 15 msg/s.  
2. **\[Pub/Sub\]** receives `viral-candidate` (Payload: `timestamp`, `streamer_id`).  
3. **\[Cloud Run "Sniper"\]** wakes up.  
   * *Query:* SQL `user_secrets` for OAuth token.  
   * *Action:* Downloads segments `T-60s` to `T+10s` from Twitch VOD.  
   * *Output:* Uploads `clip_123.mp4` to GCS.  
4. **\[Cloud Run "Director"\]** wakes up.  
   * *Action:* Sends `gs://.../clip_123.mp4` to Vertex AI.  
   * *Action:* Receives JSON analysis.  
   * *Output:* Creates doc in Firestore `users/123/cards/new_card`.  
5. **\[Frontend UI\]** (Listening to Firestore).  
   * *Action:* New Card slides in. Video auto-plays (muted).  
6. **\[User\]** Swipes Right (Approve).  
   * *Action:* Frontend updates Firestore doc `status: "approved"`.  
7. **\[Cloud Function "Publisher"\]** triggers on Firestore update.  
   * *Action:* Authenticates with Twitter API. Posts video \+ text.

### **Scenario 2: The Affiliate Link**

1. **\[GKE Sentinel\]** Audio buffer analyzes speech: "Does anyone know a good mechanical keyboard?"  
2. **\[Local Whisper\]** Transcribes text.  
3. **\[GKE Sentinel\]** Regex matches "mechanical keyboard" against cached User Config.  
4. **\[Pub/Sub\]** receives `affiliate-trigger`.  
5. **\[Cloud Function "Publisher"\]** triggers.  
6. **\[SQL Check\]** `SELECT last_posted_at FROM affiliate_links...`  
   * *Condition:* If `NOW() - last_posted_at > 10 mins`:  
   * *Action:* POST to Twitch Chat: "If you're looking for a keyboard, \[Streamer\] uses this one\! \[Link\] \#ad"  
   * *Action:* UPDATE `affiliate_links` SET `last_posted_at = NOW()`.

### **I. The High-Level GCP Topology**

We replace the AWS "Hub and Spoke" with a GCP **"Pipeline" Architecture**.

* **Orchestrator:** **Google Kubernetes Engine (GKE) Autopilot** (For the Sentinel Swarm).  
* **Event Bus:** **Cloud Pub/Sub** (Global, durable, ordered messaging).  
* **The Sniper:** **Cloud Run Jobs** (Serverless execution that runs to completion).  
* **The Brain:** **Vertex AI (Gemini 1.5 Pro)** \+ **Video Intelligence API**.  
* **Real-Time Data:** **Firestore** (Replaces DynamoDB \+ AppSync).

### **II. Service Breakdown & GCP Enhancements**

#### **1\. The Sentinel Swarm $\\rightarrow$ GKE Autopilot**

* **Why GKE?** While Cloud Run is great, maintaining 24/7 WebSocket connections to Twitch Chat (IRC) is a "stateful" workload. GKE Autopilot manages the nodes for you but lets you keep persistent pods running cheaply.  
* **Robustness Upgrade:** GKE creates a "Self-Healing" swarm. If a Sentinel pod crashes, Kubernetes restarts it instantly.  
* **Predictability:** You reserve a set amount of vCPU/RAM, making costs flat rather than fluctuating with request spikes.

#### **2\. The Event Bus $\\rightarrow$ Cloud Pub/Sub**

* **Why Pub/Sub?** It handles "at-least-once" delivery and scales globally.  
* **Robustness Upgrade:** **Dead Letter Queues (DLQ).** If the AI service crashes or fails to process a video, the event isn't lost. It moves to a DLQ topic so you can replay it later (Critical for not losing viral moments).  
* **Ordering Keys:** You can tag events with Streamer\_ID. Pub/Sub ensures events for "KaiCenat" are processed in order, preventing the "Snippet 2" from appearing before "Snippet 1".

#### **3\. The Sniper $\\rightarrow$ Cloud Run Jobs**

* **Why Jobs?** Unlike Cloud Run *Services* (which wait for HTTP requests), *Jobs* are designed to "Start $\\rightarrow$ Do Work $\\rightarrow$ Die". This fits the "Download & Stitch" task perfectly.  
* **Accuracy Upgrade:** GCP’s internal network (Premium Tier) often has better peering with video CDNs, potentially speeding up the HLS fetch.

#### **4\. The Director $\\rightarrow$ Vertex AI (Gemini 1.5 Pro)**

* **The Game Changer:** **Native Multimodality.**  
  * *AWS/OpenAI approach:* You must extract frames (images) \+ extract audio (mp3) $\\rightarrow$ send separately.  
  * *GCP approach:* **Send the video file.** Gemini 1.5 Pro can "watch" video directly. It hears the tone *and* sees the face simultaneously.  
  * *Result:* Higher **Accuracy** because the AI understands the *sync* between audio and video (e.g., a scare reaction happening *exactly* when a monster appears).

### **III. The "Robustness" Pipeline: Detailed Flow**

This design minimizes "Moving Parts" to reduce failure points.

#### **Step 1: The "Hype" Trigger (GKE)**

The Sentinel detects a spike.

* **Action:** Publishes message to Pub/Sub Topic: viral-candidates.  
* **Payload:** { "streamer": "shroud", "timestamp": "12:00:00", "hype\_score": 95 }

#### **Step 2: The "Smart" Fetch (Cloud Run Job)**

Cloud Run Job triggers off Pub/Sub.

1. **Fetch:** Uses the OAuth Token from **Secret Manager** to download the VOD segment.  
2. **Pre-Process (The Optimization):**  
   * Instead of sending *everything* to the LLM, use the **Google Cloud Video Intelligence API** (cheaper) to detect "Shot Changes."  
   * *Logic:* If the 60s clip has a 20s "Starting Soon" static screen, trim it *before* sending to the expensive AI.  
3. **Store:** Uploads clean\_clip.mp4 to **Google Cloud Storage (GCS)**.

#### **Step 3: The Analysis (Vertex AI)**

This is where we ensure **High Accuracy**.

* **Input:** gs://your-bucket/clean\_clip.mp4

**Prompt (Python SDK):**

model \= GenerativeModel("gemini-1.5-pro-preview-0409")

video \= Part.from\_uri(uri="gs://your-bucket/clip.mp4", mime\_type="video/mp4")

You are an expert stream editor.   
1\. Watch this video.   
2\. Identify the EXACT timestamp (start/end) where the funny moment happens.  
3\. Rate it 1-10.

response \= model.generate\_content(\[video, prompt\])

*   
* **Robustness:** Because Gemini "sees" the timestamps natively, it is far more accurate at cutting clips than text-only models guessing based on transcripts.

#### **Step 4: The "Tinder" UI (Firestore)**

* **Why Firestore?** It has a feature called **Realtime Listeners**.  
* **Flow:**  
  1. AI writes the Card object to a Firestore collection users/{userId}/cards.  
  2. Your Next.js frontend has a onSnapshot() listener active.  
  3. **Instantly**, without refreshing, the card pops up on the user's screen.  
  4. **Robustness:** Firestore works offline. If the user's internet flickers, the swipe action syncs when they reconnect.

* **Role:** The low-cost monitoring array.  
* **Scale:** 1 Container monitors \~50 streams.  
* **Inputs:**  
  * **Twitch Chat (IRC):** Via tmi.js or Python socket.  
  * **Audio Stream (HLS):** Via streamlink (audio\_only).  
* **Logic (The Trigger Algorithm):**  
  * Maintains a **10-second Sliding Window** of data.  
  * **Metric 1: Chat Velocity ($V\_c$):** Messages per second.  
  * **Metric 2: Emote Density ($E\_d$):** Percentage of messages containing known emotes (LUL, POG, OMEGA).  
  * **Metric 3: Audio Energy ($A\_e$):** Decibels (RMS) of the incoming audio buffer.  
  * The Formula:  
    $$HypeScore \= (V\_c \\times 0.5) \+ (E\_d \\times 0.2) \+ (A\_e \\times 0.3)$$  
  * *Threshold:* If HypeScore \> USER\_DEFINED\_THRESHOLD (e.g., 85/100) $\\rightarrow$ Emit Event.ViralCandidate.  
* **Affiliate Detection:**  
  * Runs a lightweight Whisper-tiny or Vosk (offline STT) on the audio buffer.

### **IV. Deep Dive: The Audio Sentinel ("The Watchtower")**

To avoid false positives, we need robust detection.

#### **1\. Audio Processing (Python numpy)**

We don't need full speech recognition for the trigger, just **Energy**.

* Chunk audio into 1-second frames.  
* Calculate **RMS (Root Mean Square)** amplitude.  
* **Dynamic Threshold:** Don't use a fixed "90dB". Compute the *Rolling Average* of the last 5 minutes. If current volume \> Average \* 1.5 $\\rightarrow$ **Spike**.

#### **2\. Chat Velocity (The "PogChamps" Metric)**

* Connect to Twitch IRC.  
* Store timestamps of incoming messages in a Deque (Double-ended queue).  
* *Every second:* Pop timestamps older than 10 seconds.  
* *Count:* len(deque) / 10 \= Messages Per Second (MPS).  
* **Sentiment (Optional but good):** Keep a set of "Hype Keywords" (LUL, OMG, WTF, POG, KEKW). If \> 30% of messages contain these, multiplier is 1.5x.

### **VI. Scalability & Availability Strategy**

1. **The Thundering Herd (Viral Storm):**  
   * *Scenario:* Streamer raids another streamer, chat goes crazy, false positive triggers.  
   * *Solution:* **Debouncing.** The Sentinel must enforce a "Cooldown" (e.g., 2 minutes) after a trigger prevents a second trigger.  
2. **AI Latency:**  
   * Gemini/GPT video processing takes time (10-20 seconds).  
   * *Solution:* The UI should show a "Processing..." state or just push cards to a "Review Queue" asynchronously. Do not make the user wait.  
3. **Cost Control:**  
   * If a user leaves their stream running for 24 hours while sleeping, do not run the Sentinel.  
   * *Check:* If Chat Velocity \< 1 msg/min for 10 minutes $\\rightarrow$ Paused State.
